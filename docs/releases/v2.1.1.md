# Dunzo Club v2.1.1

Release date: 28 October 2026 (India time).
Production: https://dunzo-club.arun-devanathan.workers.dev/

Priority recovery fix for players whose unconfirmed action blocked subsequent play.

## Returning to the game

Pending actions reconcile automatically after a request fails, after reconnecting
and after reload. A previously accepted action returns its saved acknowledgement;
an unaccepted action whose state version/hand has passed is rejected and cleared.
It cannot become a bet on a later turn. Manual Retry is no longer required for
normal recovery. Original command IDs and the existing durable receipts prevent
duplicate betting across HTTP and authenticated WebSocket delivery.

Failed HTTP poker requests fall back to WebSocket delivery. If WebSockets are
unavailable, HTTP snapshots restore current game state and allow play. Socket
reconnection is not gated by an HTTP session preflight. A socket policy close
alone does not sign the player out; a missing session must be confirmed. Offline
startup retries identity restoration automatically.

Other players see Disconnected after socket closure or heartbeat lease expiry.
Healthy HTTP polling or a second device keeps presence connected. Reconnection
preserves seats, stacks and future-hand eligibility. It does not set Sit Out/Away.
The game timer continues; missed turns follow the existing check/fold rules.
Chat continues using HTTP; this release does not add WebSocket chat delivery.

## Validation and compatibility

- 119 automated tests, including nine dedicated recovery tests.
- TypeScript, staging build/artifact validation and disposable actual-Worker multiplayer smoke.
- Compiled-browser fault injection: HTTP outage, accepted lost reply, both transports failing through a missed turn, WebSocket-only outage and offline reload.
- Existing mobile UI regression checks at four viewport sizes.
- Production CI build, artifact guard, dry-run and isolated production multiplayer smoke.

Physical phone network switching/background behaviour remains a manual acceptance
check; see [connection recovery testing](../CONNECTION_RECOVERY.md).

No schema or Durable Object namespace migration is required. Existing accounts,
roster, balances, sessions and hand history are retained. Refresh the web app or
close and reopen the installed PWA to load the new client. Existing open clients
need to refresh to gain the new automatic recovery behaviour.
